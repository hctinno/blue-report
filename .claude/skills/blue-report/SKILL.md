# 블루 리포트

회사 디자인을 유지하면서 비즈니스 목적에 맞는 자료를 기획·제작한다. 사용자가 정할 내용과 표현 방식을 대화로 구체화하고, 선택에 따른 차이를 설명한다.
이 스킬의 지침·자산·검사기로 작업한다. 다른 스킬이나 특정 MCP 서비스의 설치를 전제로 하지 않는다.
자료 읽기, 작업 파일·미리보기 입력 작성, 도구 준비, 렌더링과 검사는 에이전트가 수행한다. 사용자는 평범한 말로 설명하고 중요한 선택을 하면 된다.

## 1. 요청의 범위와 기획 대화

새 발표자료·발표용 보고서·덱을 요청받으면 먼저 [비즈니스 발표자료 기획 대화](references/business-presentation-intake.md)를 읽고 따른다.
주제, 목적, 청중, 사용 상황, 형식, 시간 또는 분량, 애니메이션 방침을 제작 전에 구체화한다.
지금까지의 설명과 제공 자료에서 확인된 조건을 먼저 반영하고, 아직 정해지지 않은 항목 중 중요한 질문을 한 번에 하나씩 한다.
사용자가 선택하기 어려우면 구체적인 선택지와 추천 이유를 설명한다. 위임한 항목은 추천값을 밝히고 결정한다.
“처음이라 모르겠다”에는 추천과 쉬운 선택을 제시하고, “알아서 해 달라”에는 위임한 범위를 맡아 진행한다. 이미 정한 조건은 작업 폴더의 기획 기록에 남겨 이어서 사용한다.
조건을 정리한 제작 방향과 장별 핵심 메시지를 제시한 뒤 제작한다. 이미 제작 의사와 필요한 선택이 확인됐으면 별도의 허가를 반복해서 묻지 않는다.

회의록과 관리보드는 목적에 필요한 조건을 확인해 해당 양식으로 진행한다. 발표자료의 전체 질문 절차를 적용하지 않는다.
기존 자료의 지정 문구·슬라이드만 수정하는 요청은 합의된 방향을 유지하며 요청한 부분을 수정한다.
기획이나 조사만 요청받았으면 그 범위의 결과를 전달한다.

## 2. 렌더링 이미지로 스타일 선택

기획 조건이 정리되면 [시각적 스타일 선택](references/visual-style-selection.md)을 읽고 디자인 선택 방식을 추가 옵션으로 한 번 제안한다. 전체 스타일 한 번 선택, 주요 페이지만 3안 비교, 모든 페이지 3안 비교 중에서 고를 수 있게 한다.
전체 스타일 선택은 같은 내용의 표지·본문 후보를 실제 PNG로 렌더링한다. 페이지별 비교를 선택하거나 직접 요청하면 [페이지별 3안 선택](references/page-style-selection.md)에 따라 해당 장마다 서로 다른 배치의 실제 시안 3개와 선택 화면을 만든다.
비교 이미지와 후보별 원본을 보여주고 차이와 추천 이유를 설명한다. 사용자가 고르거나 선택을 명시적으로 위임한 후 그 선택을 최종 자료에 반영한다.
이미 선택 방식·스타일이 정해졌거나 고정 양식·단순 수정을 요청한 경우 같은 질문을 반복하지 않는다. 진행 중에도 요청한 장만 페이지별 비교로 바꿀 수 있다. 애니메이션은 정지 이미지와 별도로 확인한다.

## 3. 양식과 산출물 결정

양식 이름이나 기술 옵션은 가능한 한 사용자가 설명한 목적에서 판단한다. 비즈니스 기획 질문과 양식 선택을 혼동하지 않는다.

| 요청한 결과 | 제작 경로 | 검사 |
|---|---|---|
| HTML 발표자료·보고 덱 | assets/live-standard.html을 출발점으로 구성, --deck standard | scripts/check_live.py |
| 편집 가능한 PPTX | assets/archive/의 고정 지면 덱과 pptx/ 경로 | PPTX 파일·렌더링·편집 가능 여부 |
| A4 회의록 | assets/doc-minutes.html, --deck minutes | scripts/check_doc.py |
| 수정하며 쓰는 관리보드 | assets/board-manage.html, --deck manage | scripts/check_board.py |
| 배포용 PDF | 합의한 원본 형식을 PDF로 출력 | 생성된 PDF의 실제 페이지 |

본문 디자인은 먼저 assets/live-patterns.html(패턴첩 63장, --deck patterns)에서 맞는 장을 찾아 통째로 가져오고 글·수치만 바꾼다. 패턴첩은 사내 발표 덱 최종본의 본문 디자인·연출을 형태 그대로 옮긴 것이며 내용은 가상이다. 패턴 장을 쓰면 덱 머리에 assets/blue-pattern.css를 함께 부르고 장의 xf·pt-이름 클래스를 지우지 않는다.
작은 부품은 assets/live-catalog.html에서 가져오거나 회사 규격에 맞게 구성한다.
기준 덱과 카탈로그의 장수는 견본이다. 합의한 발표 시간, 분량, 메시지에 맞게 필요한 장만 구성한다.
사용자가 PPTX를 요청하면 PPTX 경로로 제작한다. HTML의 효과·상호작용과 다른 형식의 지원 범위를 구분한다.

## 4. 제작할 때 읽을 규격

기획이 정리되어 제작으로 넘어갈 때 다음 자료를 읽는다.

- DESIGN.md: 톤, 정보 위계, 내용에 맞는 도해와 움직임 원칙. 「3」이 내용별로 먼저 볼 패턴첩 장을 가리킨다.
- MOTION.md: 효과 라이브러리. 사용자가 애니메이션·효과를 요청하면 패턴첩 장의 연출과 단일 효과 22종에서 고른다.
- references/rules.md 및 assets/blue-report.css: 문체, 색·폰트·간격·차트 규칙.
- README.md의 해당 형식과 구성 요소 사양.
- [제작 세부 절차](references/production-workflow.md): 보관 양식, 차트, PDF·PPTX 출력과 검사 명령.
- [품질 검수와 전달](references/quality-and-delivery.md): 내용 구성, 대표 장 검토, 수정과 완성본 전달.

기본 회사 로고·색·서체·머리말·꼬리말·워터마크는 제공 자산을 사용한다.
내용과 표현은 확정한 기획을 따르고, 템플릿 예시의 수치·조직·결론을 실제 사실로 사용하지 않는다.
한 장의 핵심 메시지를 명확히 하고, 청중·사용 환경에 맞는 글자 크기와 정보량을 택한다.
확인된 사실, 분석, 제안을 구분하고 수치와 주요 주장에는 자료가 뒷받침하는 출처를 연결한다.
수치 기반 차트는 검산 가능한 스크립트로 생성하고, 합의한 효과는 전달할 내용과 발표 조작에 맞게 적용한다.

## 5. 경로와 작업 파일

이 SKILL.md가 있는 폴더를 스킬 루트로 삼아 모든 참조·스크립트·자산 경로를 해석한다.
기본 회사 브랜드는 스킬 내부 brand/hct/brand.json이다. 저장소에서 직접 실행할 때는 스킬 루트 기준 ../../../brand/hct/brand.json을 사용한다. 사용자 지정 브랜드가 있으면 그 요청을 따른다.
설치된 원본은 보존하고 작업 폴더의 사본을 수정한다. 결과물은 사용자가 지정한 작업 폴더에 저장한다.
스크립트와 브랜드 파일에는 스킬 루트를 기준으로 한 정확한 경로를 사용한다. Windows의 Python 명령은 python이다.
처음 렌더링하거나 준비 문제가 생기면 scripts/ensure_deps.py --for html --check로 필요한 도구만 확인한다. 요청 형식이 PDF·PPTX면 --for pdf·pptx를 쓴다. 허용된 설치는 --prepare로 수행하며, 준비 실패를 사용자가 직접 해결해야 할 기술 질문으로 돌리지 않는다.
설치본의 출처와 버전은 INSTALLATION.json, 저장소의 스킬 버전은 .claude-plugin/plugin.json에서 확인한다.

## 6. 검수와 전달

결과 형식에 맞는 검사기를 실행하고 실제 화면을 확인한다. HTML 검사만으로 PPTX나 PDF의 검증을 대신하지 않는다.
HTML은 scripts/check_live.py, PPTX의 파일 구조·연결·텍스트는 내장 scripts/check_pptx.py로 검사한다. PPTX 파일 구조 검사만으로 화면 배치·편집 동작까지 검증했다고 말하지 않는다.
내용·메뉴명·숫자·근거와 기획 일치 여부, 글자 잘림·겹침·가독성, 발표 전환·효과·상호작용을 확인한다.
검사 실패는 수정하고, 확인하지 못한 항목은 그 범위를 밝힌다. 검사기 통과만으로 발표 전달력을 보장하지 않는다.
최종 파일의 절대경로 링크와 실제 확인한 결과를 전달하고, 합의한 목적·형식·효과가 반영된 부분을 짧게 설명한다.
