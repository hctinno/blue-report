# 추가 옵션: 페이지마다 시안 3개 고르기

사용자가 주요 페이지·모든 페이지의 3안 비교를 선택하거나, 제작 중 특정 장의 다른 디자인을 요청했을 때 읽는다. 선택 방식 질문은 [시각적 스타일 선택](visual-style-selection.md)에 있다. 이 옵션을 모든 작업의 필수 단계로 적용하지 않는다.

## 1. 비교 범위 정하기

기존 기획 기록과 현재 자료를 읽고 대상 페이지를 정한다. 사용자가 지정한 장을 우선하고, 주요 장만 비교하되 범위를 맡겼으면 표지·핵심 결과·의사결정 장처럼 목적상 중요한 장을 추천한다. 모든 장을 선택했으면 실제 전체 장수에 적용한다. 특정 주제나 장수를 고정하지 않는다.
각 장에는 순서가 바뀌어도 유지할 고유 ID를 붙인다. 비교하지 않는 장은 기존 스타일을 유지한다. 완료된 기획 질문이나 전체 스타일 선택을 다시 요구하지 않는다.
기존 원본은 보존하고 작업 폴더에 후보·미리보기·선택 기록을 만든다. 비교 대상과 전체 후보 수를 짧게 알린 뒤 바로 시안을 제작한다.

## 2. 같은 내용으로 서로 다른 3안 만들기

각 장의 제목·핵심 메시지·수치·범위·출처와 필요한 설명을 고정한 뒤 A·B·C를 만든다. 색만 바꾸거나 다른 정보를 넣어 후보 수를 채우지 않는다. 정보의 배치·위계·도해 방식이 눈으로 구분되게 구성한다.
예를 들어 결론과 근거의 좌우 배치, 큰 핵심 문장과 비교 도표, 단계 흐름이나 결정 목록처럼 해당 내용에 맞는 차이를 준다. 세 후보는 디자인 언어(references/design-language.md)의 서로 다른 배치 문법을 내용에 맞게 응용해 만들면 회사 발표 덱의 색·위계·움직임이 유지된다. 패턴첩(assets/live-patterns.html)은 그 문법의 용례이며 그대로 베끼지 않는다. 세 방향을 모든 장에 기계적으로 복제하지 않는다.
회사 로고·브랜드 색·서체·머리말·꼬리말·워터마크와 공통 여백 규격을 유지한다. 후보를 섞어도 하나의 자료로 읽히게 한다. 장마다 추천안을 둘 수 있지만 추천을 실제 선택으로 저장하지 않는다.
각 후보를 실제로 렌더링한 PNG로 저장한다. 표·도표·글자 잘림을 확인하고 후보 간 내용과 출처가 같은지 대조한다. 텍스트 설명만으로 시안을 보여줬다고 하지 않는다. 추가 AI 이미지 생성은 이 옵션의 필수 조건이 아니다.

## 3. 비교·확대·선택 화면 제공

대상 장마다 실제 PNG 3개, 후보 이름, 차이와 추천 이유를 담은 작업 폴더의 index.html을 만든다. 큰 이미지 보기와 페이지별 A·B·C 선택을 제공하고, 현재 선택 수와 미선택 장을 표시한다. 모바일에서는 카드가 세로로 이어지게 한다.
처음에는 미선택 상태로 두고 실제 사용자 선택 또는 명시적인 위임만 반영한다. 추천 조합을 일괄 적용하려면 별도 버튼으로 제공한다. 기존 선택을 불러올 때는 같은 자료·같은 후보에 대한 기록인지 확인한다.
브라우저 선택 보관에는 자료별 키를 쓰고, 선택 내용을 `1-B, 2-A, 3-C`처럼 대화에 복사할 수 있게 한다. 로컬 브라우저 선택이 대화에 자동 전달된다고 가정하지 않는다. 사용자가 선택 내용을 전달하거나 적용을 요청했을 때 선택 기록을 읽어 반영한다.
가능하면 비교 이미지를 대화에도 보여주고 선택 화면의 절대경로 링크를 제공한다. 사용자에게 JSON 작성이나 명령 실행을 요구하지 않는다. 후보를 보여준 뒤 원하는 조합을 고르게 하되 같은 선택을 별도 승인으로 다시 묻지 않는다.

## 4. 선택을 기록하고 결과물에 반영

작업 폴더의 page-styles.json에 선택 방식, 비교한 페이지 ID, 각 후보의 파일, 실제 선택 ID와 선택 근거를 기록한다. blue-report-brief.md의 선택과 일치시킨다. 전체 스타일 하나를 고른 것으로 혼합 선택을 덮어쓰지 않는다.

```json
{
  "selection_mode": "all_pages",
  "pages": [
    {
      "id": "summary",
      "number": 1,
      "variants": {
        "A": {"name": "결론과 근거", "preview": "previews/summary-A.png"},
        "B": {"name": "핵심 문장 강조", "preview": "previews/summary-B.png"},
        "C": {"name": "비교 중심", "preview": "previews/summary-C.png"}
      },
      "recommended": "B",
      "selected": null,
      "selection_source": null
    }
  ]
}
```

selection_mode는 주요·지정 장 비교인 selected_pages 또는 전체 비교인 all_pages를 쓴다. selected와 selection_source는 실제 응답·브라우저 선택·명시적 위임이 있을 때만 채운다. 위 예시는 입력 구조이며 실제 장의 내용과 파일로 에이전트가 작성한다.
선택이 아직 없는 장은 미결로 표시하고 자료 확인·내용 정리는 계속한다. 사용자가 선택을 위임하지 않았다면 추천안으로 완성본을 임의 확정하지 않는다. 이미 선택한 장의 결정을 다시 받지 않는다.

HTML은 선택한 장들을 합쳐 한 벌로 미리보고 저장할 수 있게 한다. 후보마다 필요한 CSS·폰트·도표·발표 동작을 함께 보존한다. HTML을 파싱할 때는 실제 덱의 main 요소 안에서 슬라이드를 추출해 CSS 주석이나 예시 코드의 section 문자열을 슬라이드로 잘못 취급하지 않는다. 선택한 순서·장수·내용·출처와 클릭 전개를 합친 파일에서 검증한다.
PPTX·PDF는 고른 디자인을 해당 형식으로 제작해 실제 렌더링 결과를 확인한다. HTML 선택 화면이나 PNG만으로 편집 가능한 PPTX를 만들었다고 하지 않는다. 여러 형식을 요청받으면 각 결과에 선택 조합이 반영됐는지 확인한다.

## 5. 전달 전 확인

대상 장마다 실제 후보 3개가 있는지, 확대·선택·선택 내용 복사가 동작하는지, 서로 다른 장의 조합이 반영되는지 확인한다. HTML 저장 기능을 제공했다면 저장한 파일을 다시 열어 발표 동작까지 확인한다.
최종 결과의 글자 잘림·겹침·가독성과 장 사이의 일관성을 검사한다. 형식별 기본 검사도 실행한다. 비교하지 않은 장과 원본 자료가 뜻하지 않게 바뀌지 않았는지 확인한다.
전달할 때 선택 화면·최종 파일의 절대경로 링크와 실제 확인한 결과만 짧게 설명한다. 사용자가 변경을 요청하면 해당 장의 후보·선택만 갱신한다.
