## 1. 차트

### 1.1 도넛 (파이 금지)

파이는 쓰지 않는다. 손으로 적은 `<path d="M0 0 L… A…">`는 수치와 각도가 어긋나므로 금지한다.
도넛은 원주 기반 `stroke-dasharray`로만 그린다.

```
C    = 2 × π × r                       원주
dash = C × pct/100  −  C × 1.5/360     구간 길이 (1.5도 간격 차감)
rot  = 누적pct × 3.6 − 90              12시에서 시작
```

```html
<circle class="dsh d5" r="110" stroke="var(--br-data-1)" stroke-width="48"
        stroke-dasharray="400.8 691.2" transform="rotate(-90)"></circle>
```

- `stroke-dasharray`의 두 번째 값은 **항상 원주 C**다. 이 값이 다르면 구간이 반복된다.
- 계산은 `scripts/donut.py`가 한다. 직접 계산하지 않는다.
- 구간은 3~5개. 6개를 넘으면 막대로 바꾸거나 하위 구간을 '기타'로 묶는다.
- 구간이 간격(1.5도)보다 작으면 보이지 않는다. 스크립트가 경고한다.

### 1.2 라벨 배치

- 라벨은 **도넛 밖**에 둔다. 좁은 홀에 텍스트를 넣지 않는다.
- 기본은 도넛 아래 `.br-legend`. 구간명과 값을 세로로 쌓고 앞에 `.br-dot` 구간색 점을 붙인다.
- 리더 라인이 필요하면 꺾은선 + 구간색 점(r=6)으로 연결한다. 선이 호를 가로지르지 않게 한다.

### 1.3 막대

- **값은 막대 안이 아니라 전용 컬럼 또는 막대 위 줄에 둔다.** 퍼센트 폭 안에 텍스트를 넣으면
  짧은 값에서 삐져나온다.
- 세로 막대: 값 → `.br-col-val` (막대 위), 이름 → `.br-col-name` (차트와 다른 그리드 형제).
  이름을 절대 위치로 막대 위에 올리지 않는다.
- 가로 막대: `.br-bars-h`가 `이름 / 채널 / 값`을 서로 다른 그리드 컬럼으로 분리한다.
- 높이 = `값 / 최댓값 × 채널높이`. 채널높이는 470px를 기준으로 잡는다.
- `border-radius = 높이/2`인 막대는 값이 높이보다 좁아지면 전부 같은 캡슐로 보인다.
  좁은 채널(가로 막대)은 2px, 넓은 세로 막대만 8px.

### 1.4 색

- **데이터 마크(호·막대·버블·범례 스와치)는 지면 대비 2:1 이상.** 배경·구분선 톤을 데이터에 쓰지 않는다.
- 인접 구간에 같은 색 금지. 값이 클수록 진한 **단조 램프**.
- 부품 넷 — 질문 칩 `.br-ask` · 아이소타입 `.br-iso` · 다크 요약장 `.br-sumcard` ·
  지시선 주석 `.br-note`. 아이소타입은 분모가 정수 칸으로 떨어질 때만 쓴다.
  지시선 주석은 한 지면에 하나만, **세로 막대(`.br-bar-v`) 안에만** 둔다 —
  가로 막대 트랙은 `overflow:hidden` 이라 잘라 낸다. 넷 다 HTML 전용이며
  PPTX 는 그리지 않는다. 자리가 없는 덱에 억지로 넣지 않는다.
- **카드에 테두리를 두르지 않는다.** 흰 카드 + 그림자가 요점, `.br-card--mute`(틴트, 그림자 없음)가
  대조군이다. 그림자 유무가 위계를 만든다.
- **본문 잉크는 y 1000px 아래로 내려가지 않는다.** 푸터까지 완충을 둔다.
- **색은 값의 크기가 아니라 "무엇을 보라"로 정한다.** 주인공은 기본값(`--mark`),
  맥락은 `--mute` 클래스(`.br-bar-v--mute` · `.br-bar-h--mute` · `.br-col-name--mute`).
  마크업에 `background` 를 직접 적지 않는다. 몇 개를 주인공으로 둘지는 제목이 정한다.
- 단조 램프는 **순서가 있는 구간**에만 쓴다. 부서·제품처럼 순서 없는 항목에 쓰지 않는다.
- 밝은 지면용 5색: `--br-data-1` ~ `--br-data-5` (12.44 / 7.11 / 3.58 / 2.73 / 2.10 : 1).
- 구간 6개 이상이면 `python3 scripts/palette.py --steps N`으로 보간 램프를 만든다.
  7단계는 `--br-bar-1` ~ `--br-bar-7`로 이미 토큰에 있다.
- `--br-soft-1~3`(`#7fb6f5 #9dc4f2 #a4c4e5`)은 밝은 지면에서 1.67~1.96:1로 **2:1에 미달한다.**
  다크면 위 데이터, 또는 밝은 면의 비데이터 요소(보조 텍스트·구분선)에만 쓴다.

### 1.5 버블

면적 비례로 그린다. 지름 비례는 큰 값을 과장한다.

```
d = k × √value
```

## 2. 레이아웃 체크리스트

새 슬라이드를 만들면 반드시 확인한다. `scripts/check_deck.py`가 1·4·5·6·7·8과 문체를
자동 검사한다(판정 17항목). 2는 눈으로 본다. `실패`가 0이 아니면 완료가 아니고,
`주의`는 허용된다.

1. `section.scrollHeight === 1080`, `scrollWidth === 1920`
   넘치면 `flex:1` 컨테이너에 `min-height:0`을 주고 행 높이를 줄인다.
2. 절대 위치 라벨이 차트를 덮지 않는가 → 차트와 라벨은 **다른 그리드 컬럼 또는 flex 형제**로 분리
3. 푸터(`.br-footer`)가 콘텐츠와 겹치지 않는가 → 항상 마지막 형제, `flex-shrink:0`
4. 24px 미만 텍스트가 없는가 (`.br-sup` % 첨자만 예외)
5. 데이터 마크 대비 2:1 이상, 인접 색 중복 없음
6. 파이 `<path>` 없음, 도넛 dasharray가 원주와 일치
7. 토큰 밖 raw hex 없음
8. 우측 상단 `.br-mark`가 있는가 → 본문과 겹치지 않고, `data-on`이 배경 밝기와 일치해야 한다
   (어두운 면 `dark`=흰색 로고 · 밝은 면 `light`=원색 로고)

빈 공간이 크게 남으면 내용을 늘리기 전에 배치를 먼저 본다. 목록은 `justify-content:space-between`,
카드는 하단에 `margin-top:auto` 요약 행(기간·출처·합계)을 두면 대개 해결된다.

## 2-2. 기준 덱 · 라이브 덱 체크리스트

고정 지면이 없는 계통이다. `scripts/check_live.py` 가 22항목을 판정한다.
**새 보고서는 `assets/live-standard.html` 을 복사해 시작하고, `apply_brand.py --deck standard
--single-file` 로 산출물을 만든다.**

1. 치수를 `rem` 으로만 적었는가 → `px` 는 1px 테두리, 배율 엔진의 `clamp`, blur/shadow 반경만 예외
2. 머리띠 `.bl-hd` 가 장마다 있는가 → `.bl-code`(절 번호+이름) · `.bl-sp` · `.br-mark`
3. 꼬리띠 `.bl-rf` 와 쪽번호 `.bl-pg` 가 장마다 있는가
4. 워터마크 `.br-watermark` 가 장마다 있는가
5. `data-on` 짝이 맞는가 → **머리띠 마크는 지면과 반대다**

   | 지면 | 띠 색 | 머리띠 마크 | 워터마크 |
   |---|---|---|---|
   | 밝은 장 | 짙음 | `dark` | `light` |
   | 어두운 장 `bl-sl--dark` | 흼 | `light` | `dark` |

   `data-on` 은 「이 마크가 어떤 배경 위에 앉는가」다. 머리띠 마크가 앉는 곳은 지면이
   아니라 띠이고, 띠 색은 지면과 반대다. 틀려도 로고가 배경에 묻힐 뿐 사라지지는 않아
   눈으로는 알아채기 어렵다 — 검사기가 잡는다.
6. 본문 글자가 1.0rem 이상인가 → 주석 계열(`.bl-note` · `.bl-src` · `.bl-ord` 등)만 예외, 절대 하한 0.78rem
7. 제목의 핵심구를 `<em>` 으로 감쌌는가 → 형광 밴드가 거기에만 걸린다
8. `.br-mark` · `.br-watermark` 안의 자리표시자 마크업을 그대로 두었는가 → `apply_brand.py` 가 채운다
9. 산출물에 「COMPANY NAME」이 남지 않았는가 → 견본(`assets/` 아래)만 예외. 복사해 내용만 바꾸고
   `apply_brand.py` 를 안 거치면 로고도 워터마크도 없는 덱이 나온다
10. 스타일과 본문 폰트가 실제로 붙었는가 → 계통 CSS 토큰과 Pretendard `FontFace` 를 렌더에서 확인.
    `--single-file` 없이 낸 산출물에서 CSS 를 떼어 옮기면 Times New Roman 이 된다
11. 지면이 화면 좌우 끝까지 닿는가 → body 기본 여백 8px 이 살아 있으면 띠가 끝에 안 닿는다
12. 출처 칩 `.bl-ev` 이 근거에 이어지는가 → 키가 `#bl-evidence` JSON 에 있고, 항목마다 제목·등급·출처
    · 등급은 A 1차 공식 자료 · B 학술·전문기관 · C 언론·2차 자료 · R 직접 조회·집계
13. 떠 있는 조작판이 꼬리띠 글자(문서명·쪽번호)를 덮지 않는가 → 1600·760·400px 에서 잰다.
    600px 이하(휴대폰)는 조작판에 ‹ › 만 남는다 — 나머지는 발표자 화면의 조작이다

빈 공간은 아래에 모으고 억지로 늘리지 않는다. 격자에 `.bl-fill` 을 주면 블록이 남는 자리를

## 3. 문체

- **개조식 · 명사형.** 슬라이드 본문은 명사로 끝낸다.
  - 존댓말 종결 금지 — `~합니다 / ~습니다 / ~입니다 / ~됩니다 / ~해요 / ~어요`
  - **평서형 종결도 금지** — `~한다 / ~된다 / ~없다 / ~았다·었다` 등 `다` 로 끝나는 서술
  - 예: `진단으로 푼다` → `진단으로 해결`, `시작도 안 됐다` → `시작 전`
  예외는 설문 문항과 응답 선택지 원문뿐이며, 그 줄에 `<!-- 원문 -->` 주석을 남긴다.
  발표자 노트(`data-notes`)는 대상이 아니다.
- 긴 서술은 `키워드 — 내용`으로 쪼갠다. `.br-split`이 이 구조를 쓴다.
- 핵심 수치·개념은 `<span class="br-key">`로 감싼다 (700 굵기 + 딥네이비).
- **한 슬라이드 = 한 주장.** 문장 수를 줄이고 한눈에 스캔되게 한다.
- 제목은 weight 300과 900을 한 문장에서 대비시킨다.
  `<h2 class="br-title br-title--light">가벼운 앞말 <strong>굵은 핵심</strong></h2>`

## 4. 애니메이션

`[data-deck-active]`가 붙은 슬라이드에서만 재생된다. 뷰어가 활성 슬라이드에 이 속성을 넣는다.

| 클래스 | 동작 | 쓰는 자리 |
|---|---|---|
| `.a` | fade-up | 제목·본문·카드 기본값 |
| `.ad` | fade-down | 섹션 라벨(제목 위) |
| `.f` | fade | 푸터·축 이름 |
| `.bx` | scale-X | 가로 막대 |
| `.by` | scale-Y | 세로 막대 |
| `.p` | pop | 단일 수치 강조 |
| `.dsh` | dasharray | 도넛 구간 |

딜레이 `.d1`~`.d12` = 80ms 단위. 순서는 **제목 → 본문 → 차트**.
마지막 딜레이가 1초를 넘지 않게 한다. 넘으면 요소가 너무 많은 것이므로 슬라이드를 쪼갠다.

`prefers-reduced-motion: reduce`에서는 전부 꺼진다. 애니메이션에 의존해 정보를 전달하지 않는다.

## 5. 형태

- 카드 라운드 18px (`--br-r-card`). 그림자는 `--br-card-shadow` 하나만.
- **지면 가운데에 워터마크(`.br-watermark`).** 720px · `z-index:-1`.
  **표지 한 장만 뺀다.** 그 밖의 모든 지면에 깔린다.
  다크·표지 조판은 흰색 녹아웃 5%, 밝은 지면은 원색 3%.
  **국문 병기를 뗀 심볼만 쓴다.** `make_logo_variants.py` 가
  `<이름>-symbol-white.png` · `-symbol-color.png` 두 벌로 만들어 준다. 손으로 자르지 않는다.
  `.br-slide` 의 `isolation:isolate` 가 있어야 배경 뒤로 내려가지 않는다.
- **카드는 밝은 지면 전용.** 다크면에서는 CSS 가 바탕·테두리를 걷어내고 상단 괘선
  2px 으로 바꾼다. 짙은 면 위 짙은 판은 대비 1.12:1 이라 뭉개진다.
  다크면에 판을 다시 그리지 않는다.
- 알약 칩(`.br-chip`)은 **한 줄 전용**이며 그림자를 주지 않는다.
  좁은 컬럼에서 두 줄이 되면 `.br-chip--rect`(라운드 18px)로 바꾼다.
- 제목 밑줄, 장식용 색 띠, 사이드 스트라이프를 쓰지 않는다.
  단계 구분이 꼭 필요한 카드만 `.br-card--step`의 상단 굵은 테두리를 허용한다.
- 블루프린트 `+` 코너 마크는 쓰지 않는다. 라운드 카드와 충돌한다.
